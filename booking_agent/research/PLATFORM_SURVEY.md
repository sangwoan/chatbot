# 예약·티켓 사이트 자동 감시 가능 여부 조사 (2026-10-19, 갱신 2026-10-20)

국내 72곳 + 해외 78곳 = 150곳. 많이 쓰이는 예약·티켓 사이트를 골라 만든 목록이며 트래픽 순위는 아니다.

## 방법

- 사이트마다 일반 요청 최대 3번: robots.txt → 대상 페이지 → 약관 페이지. robots.txt가 막은 페이지는 열지 않았다. 브라우저 자동화·우회는 쓰지 않았다(`check_sites.py`).
- 공식 알림·대기·API와 주요 사이트 약관·매크로 단속은 웹 검색으로 따로 확인했다.
- 온보딩하며 직접 확인한 사이트는 판정 근거에 확인일을 적었다.
- 법률 판단이 아니다.

## 판정 기준

| 판정 | 뜻 |
|---|---|
| 불가 · 봇 차단 | robots.txt가 일반 봇 전체 금지, robots.txt부터 403, 일반 요청이 차단·챌린지, 또는 잔여 조회에 매크로 방지·대기열 적용 |
| 불가 · 약관 금지 | 약관의 자동화·스크레이핑 금지 조항 확인, 또는 매크로 적발 제재 보도 |
| 비권장 · 봇 방어 | Akamai Bot Manager·DataDome·PerimeterX·Kasada·Imperva·AWS WAF·F5 흔적. 자동 조회가 막힐 가능성이 높고, 막힌 뒤 계속하면 우회가 된다 |
| 비권장 · 매크로 단속 | 국내 티켓 예매처·NOL 계열처럼 매크로 감시·강제 취소가 보도된 곳 |
| 조건부 · 약관 확인 필요 | robots 허용, 차단 없음, 봇 방어 미감지. 약관에 금지 조항이 없을 때만 알림 전용·60초 이상 간격·정직한 식별로 감시 후보. 차단되면 즉시 중단 |

- 자동 감시를 명시적으로 **허용**한다고 밝힌 예약 사이트는 찾지 못했다.
- 가장 확실한 방법은 사이트가 직접 주는 **공식 알림·대기·API**다(아래 표).
- 국내 공공 예약 시스템은 잔여 조회 자체에 매크로 방지(동적 경로)·대기열(NetFUNNEL)을 거는 경우가 많다. 서울시 공공예약·국립공원이 그랬고, 대신 공식 대기신청이 있는 곳이 많다.

## 한계

- robots.txt는 Python `robotparser`로 판독했다(와일드카드 미지원). 구글 항공권·똑닥·에어서울은 원문을 보고 고쳤다.
- 봇 방어 흔적은 첫 페이지 기준이다. 실제 예약 조회 API는 더 강하게 막혀 있을 수 있다(서울시 공공예약·국립공원 사례).
- 약관 자동 검사는 첫 페이지에서 약관 링크를 찾은 경우만 했다. 나머지는 '미확인'이다.
- SRT는 2026-09-01 KTX(코레일+)로 통합됐다.
